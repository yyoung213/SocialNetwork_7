# Post-Post 네트워크 군집 분석 (Community Detection)

## 개요
본 문서는 Post-Post One-mode Projection 네트워크에 대한 커뮤니티 탐지(Community Detection) 분석 결과를 정리합니다.

**분석 목적**: 
- 공고 간 유사성 기반 네트워크에서 자연스러운 그룹(커뮤니티) 식별
- 직군별 경계의 명확성 검증
- 유사한 스킬을 요구하는 공고들이 실제로 같은 커뮤니티로 묶이는지 확인

**네트워크 특성**:
- 전체 네트워크 규모: 1,272개 노드(공고), 423,728개 엣지
- 네트워크 밀도: 약 0.524 (매우 밀집된 네트워크)
- 알고리즘: Louvain 알고리즘 (Blondel et al. 2008) - Gephi와 동일한 설정
- **알고리즘 파라미터**:
  - Resolution: 1.0
  - Randomize: On
  - Use edge weights: On
- **모듈성 (Modularity)**: 0.1672

---

## 1. 커뮤니티 탐지(Community Detection)란?

### 1.1 개념
**커뮤니티 탐지(Community Detection)**는 네트워크 내에서 밀접하게 연결된 노드들의 그룹을 식별하는 기법입니다. 이러한 그룹을 '커뮤니티(Community)' 또는 '군집(Cluster)'이라고 하며, 네트워크의 구조적 특성을 파악하는 데 핵심적인 역할을 합니다.

### 1.2 커뮤니티의 의미
- **내부 연결성**: 같은 커뮤니티 내 노드들은 서로 밀접하게 연결되어 있습니다.
- **외부 분리성**: 다른 커뮤니티 간의 연결은 상대적으로 약합니다.
- **의미적 유사성**: 같은 커뮤니티에 속한 노드들은 유사한 특성을 공유합니다.

### 1.3 본 분석에서의 의미
Post-Post 네트워크에서 커뮤니티는 **유사한 스킬을 요구하는 공고들의 그룹**을 의미합니다. 이는 직군별 경계가 실제로 명확한지, 아니면 여러 직군이 유사한 스킬을 요구하여 혼재되는지를 검증하는 데 사용됩니다.

## 2. Louvain 알고리즘

### 2.1 알고리즘 개요
**Louvain 알고리즘**은 모듈성(Modularity) 최적화를 기반으로 한 커뮤니티 탐지 알고리즘입니다. 본 분석은 **Gephi와 동일한 설정**으로 수행되었습니다.

**참고 문헌**: 
- Vincent D Blondel, Jean-Loup Guillaume, Renaud Lambiotte, Etienne Lefebvre, 
  "Fast unfolding of communities in large networks", 
  Journal of Statistical Mechanics: Theory and Experiment 2008 (10), P1000

### 2.2 알고리즘 파라미터 (Gephi 설정)
- **Resolution**: 1.0
  - 해상도 파라미터는 커뮤니티 크기를 조절합니다.
  - 값이 클수록 더 작은 커뮤니티를 생성합니다.
  - 1.0은 기본값으로, 네트워크의 자연스러운 커뮤니티 구조를 탐지합니다.
- **Randomize**: On
  - 노드 처리 순서를 랜덤화하여 다양한 초기 조건에서 최적화를 수행합니다.
  - 이는 더 나은 모듈성을 찾을 수 있게 해줍니다.
- **Use edge weights**: On
  - 엣지 가중치를 고려하여 커뮤니티를 탐지합니다.
  - 가중치가 높은 연결(더 많은 공유 스킬)을 더 중요하게 고려합니다.

### 2.3 작동 원리
1. **초기화**: 각 노드를 개별 커뮤니티로 시작
2. **최적화**: 각 노드를 인접 커뮤니티로 이동시켜 모듈성 증가 시도
3. **집계**: 커뮤니티를 단일 노드로 집계하여 상위 레벨 네트워크 생성
4. **반복**: 더 이상 모듈성이 증가하지 않을 때까지 반복

## 3. 모듈성(Modularity) 해석

### 3.1 모듈성의 정의
**모듈성(Modularity)**은 네트워크의 커뮤니티 구조 품질을 평가하는 지표입니다. 

**수식**: Q = (커뮤니티 내 실제 연결 비율) - (랜덤 네트워크에서 기대되는 연결 비율)

### 3.2 모듈성 값의 범위와 해석
모듈성은 **-1에서 1 사이의 값을 가집니다**. (절대 3을 넘을 수 없습니다)

| 모듈성 값 | 해석 | 의미 |
|---------|------|------|
| **0.7 이상** | 매우 강한 커뮤니티 구조 | 커뮤니티 경계가 매우 명확함 |
| **0.3 ~ 0.7** | 좋은/명확한 커뮤니티 구조 | 커뮤니티 경계가 비교적 명확함 |
| **0.0 ~ 0.3** | 약한/중간 정도의 커뮤니티 구조 | 커뮤니티 경계가 모호하거나 약함 |
| **0.0 근처** | 랜덤 네트워크와 유사 | 커뮤니티 구조가 거의 없음 |
| **음수** | 나쁜 분할 | 커뮤니티 분할이 랜덤보다 나쁨 |

### 3.3 본 분석의 모듈성: 0.1672
**해석**: 
- 모듈성 0.1672는 **0.3보다 낮은 값**으로, 네트워크가 **약한~중간 정도의 커뮤니티 구조**를 가지고 있음을 의미합니다.
- 이는 커뮤니티 경계가 완전히 명확하지 않으며, 여러 직군이 유사한 스킬을 요구하여 혼재되어 있을 가능성을 시사합니다.
- 랜덤 네트워크(0.0)보다는 구조가 있지만, 강한 커뮤니티 구조(0.3 이상)라고 보기는 어렵습니다.

**주의사항**: 
- 이전 문서에서 "명확한 커뮤니티 구조"라고 표현한 것은 부정확했습니다.
- 0.1672는 중간 정도의 구조를 의미하며, 해석에 주의가 필요합니다.

### 3.4 모듈성이 낮은 이유 분석
1. **네트워크 밀도가 매우 높음**: 1,272개 노드에 423,728개 엣지로, 거의 모든 공고가 서로 연결되어 있습니다.
2. **직군 간 스킬 유사성**: 데이터 관련 직군들(데이터 엔지니어, 데이터 분석가, 데이터 사이언티스트, 머신러닝 엔지니어)이 유사한 스킬을 요구하여 경계가 모호합니다.
3. **샘플 수 불균형**: 머신러닝 엔지니어(470개)와 데이터 엔지니어(306개)가 많아 네트워크를 지배하고, 소규모 직군(BI 엔지니어 9개)은 제대로 표현되지 않았을 수 있습니다.

## 5. 직군별 경계 명확성 분석

### 5.1 평가 지표
- **평균 지배도 (Average Dominance Ratio)**: 0.617
  - 각 커뮤니티에서 가장 많은 직군이 차지하는 비율의 평균
  - 값이 1에 가까울수록 커뮤니티가 단일 직군으로 구성됨을 의미
  - 0.617은 중간 수준으로, 일부 커뮤니티는 단일 직군, 일부는 혼재
  
- **평균 직군 다양성 (Average Job Type Diversity)**: 0.581
  - 각 커뮤니티 내 직군의 다양성을 나타내는 지표 (Shannon Entropy 기반)
  - 값이 0에 가까울수록 단일 직군, 1에 가까울수록 다양한 직군이 혼재
  - 0.581은 중간~높은 수준으로, 대부분의 커뮤니티가 여러 직군을 포함

### 5.2 해석
- **직군 경계가 중간 수준**: 평균 지배도가 0.617로, 일부 커뮤니티는 단일 직군으로 구성되지만 일부는 혼재되어 있습니다.
- **직군 다양성이 중간~높은 수준**: 평균 다양성이 0.581로, 대부분의 커뮤니티가 여러 직군을 포함하고 있습니다.
- **결론**: 직군별 경계가 완전히 명확하지 않으며, 데이터 관련 직군들이 유사한 스킬을 요구하여 혼재되어 있습니다.

### 5.3 샘플 수 차이의 영향
- **대규모 직군의 지배**: 머신러닝 엔지니어(470개)와 데이터 엔지니어(306개)가 큰 커뮤니티를 형성
- **소규모 직군의 표현 부족**: BI 엔지니어(9개)는 네트워크에서 거의 보이지 않음
- **커뮤니티 크기와 샘플 수의 상관관계**: 커뮤니티 크기가 직군의 실제 중요도가 아니라 샘플 수의 영향을 받을 수 있음

## 7. 인사이트 및 결론

### 7.1 주요 발견사항

1. **커뮤니티 구조의 특성**
   - 총 5개의 커뮤니티가 탐지되었으며, 평균 크기는 254.4개 공고입니다.
   - 상위 3개 커뮤니티가 전체의 96.8%를 차지하여 크기 불균형이 심합니다.
   - 모듈성 0.1672는 약한~중간 정도의 커뮤니티 구조를 의미합니다.

2. **직군 경계의 명확성**
   - 직군별 경계가 부분적으로 나타나고 있습니다.
   - 일부 커뮤니티(프로덕트 매니저 커뮤니티)는 단일 직군으로 구성되지만, 대부분의 커뮤니티는 여러 직군이 혼재되어 있습니다.
   - 이는 데이터 관련 직군들이 유사한 스킬을 요구하거나, 직군 분류가 완전히 명확하지 않을 수 있음을 시사합니다.

3. **모듈성의 의미**
   - 모듈성 0.1672는 **약한~중간 정도의 커뮤니티 구조**를 의미합니다.
   - 이는 네트워크의 높은 밀도, 직군 간 스킬 유사성, 샘플 수 불균형 등이 영향을 미쳤을 가능성이 있습니다.
   - "명확한 커뮤니티 구조"라고 보기는 어렵습니다.

4. **샘플 수 차이의 영향**
   - 머신러닝 엔지니어(470개)와 데이터 엔지니어(306개)가 큰 커뮤니티를 형성
   - BI 엔지니어(9개)는 네트워크에서 거의 보이지 않음
   - 커뮤니티 크기가 직군의 실제 중요도가 아니라 샘플 수의 영향을 받을 수 있음

### 7.2 시사점

1. **직군 분류의 재검토 필요성**
   - 데이터 관련 직군들(데이터 엔지니어, 데이터 분석가, 데이터 사이언티스트, 머신러닝 엔지니어)이 유사한 스킬을 요구하여 네트워크에서 혼재되어 있습니다.
   - 이는 직군 분류 기준을 재검토하거나, 더 세분화된 분류가 필요할 수 있음을 시사합니다.

2. **네트워크 구조의 특성**
   - 매우 높은 네트워크 밀도(0.524)로 인해 거의 모든 공고가 서로 연결되어 있습니다.
   - 이는 공고들이 많은 공통 스킬을 요구하거나, 스킬 사전이 너무 포괄적일 수 있음을 시사합니다.

3. **분석 방법론의 한계**
   - 샘플 수 불균형이 커뮤니티 구조에 큰 영향을 미칩니다.
   - 소규모 직군의 표현이 부족하여, 네트워크 구조가 실제 시장 구조를 완전히 반영하지 못할 수 있습니다.

### 7.3 제한사항 및 향후 연구 방향

1. **제한사항**
   - 샘플 수 불균형으로 인한 편향
   - 네트워크 밀도가 매우 높아 커뮤니티 경계가 모호함
   - 스킬 추출 방법의 한계 (텍스트 매칭 기반)

2. **향후 연구 방향**
   - 샘플 수를 고려한 정규화 분석 수행
   - 가중치 필터링을 통한 네트워크 밀도 조절
   - 다른 커뮤니티 탐지 알고리즘과의 비교 분석
   - 해상도 파라미터 조정을 통한 다양한 커뮤니티 구조 탐색

## 8. 참고사항

### 8.1 모듈성 해석 기준
- 모듈성은 **-1에서 1 사이의 값을 가집니다** (절대 3을 넘을 수 없습니다).
- 0.3 이상이면 비교적 뚜렷한 커뮤니티 구조로 해석됩니다.
- 본 분석의 0.1672는 0.3보다 낮아 약한~중간 정도의 구조를 의미합니다.

### 8.2 커뮤니티 탐지의 목적
- 커뮤니티 탐지는 네트워크의 **구조적 특성**을 파악하는 것이 목적입니다.
- 결과는 네트워크의 구조를 반영하며, 실제 의미적 그룹과 완전히 일치하지 않을 수 있습니다.
- 해석 시 네트워크 특성(밀도, 샘플 수, 가중치 분포 등)을 함께 고려해야 합니다.
